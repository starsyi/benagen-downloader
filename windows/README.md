## 0. 构建：产物在哪

```bash
# 在仓库根目录跑（脚本自己解析路径，cwd 无所谓）
bash windows/scripts/build_windows.sh
```

产物是**一个 exe**（单文件分发，W-4）：

```
windows/dist/BenagenDownloader-Windows-x86_64.exe
```

⚠️ `dist/` 是**可再生产物、不入库**。要交给客户的只有上面那一个文件 ——
内核（`benagen-core.exe`）是**内嵌在它里面**的，首次运行时释放到
`%LOCALAPPDATA%\BenagenDownloader\cache\`（第 4 条就是验这件事）。

**构建脚本自己验产物**（W-1），而且这些判据**在交付形态那一个文件上各跑一遍**：
PE32+ x86-64、GUI 子系统（不是 console）、依赖表里只有系统 DLL
（**没有** `WebView2Loader.dll`、**没有** mingw 运行时）、版本资源与 manifest 在位、
**三份**许可全文与字体子集都在里面。任何一条不过就 `EXIT != 0` 并指名说清是哪一条。

> 🔑 **交付 exe 现在是可复现的**（任务 15 修好的）。构建脚本第 4d 步会**当场**证明
> 这件事：它先判 PE 头里的链接时刻是 0，再**删掉产物、隔 2 秒重新链一次**、
> 两份字节逐字节比。跑完最后一行会打出

```
build_windows.sh: sha256：<64 位十六进制>
build_windows.sh: 可复现：连链两次逐字节相同（判据在第 4d 步）——
```

> ⇒ **把那个 sha256 抄下来，填进 §1 的开头。** 从此"我测的是哪一个"有唯一答案。
> （在 2026-09-20 之前它不是可复现的：同一棵树连跑两次体积相同、sha256 不同 ——
> 根因是 mingw 的 `ld` 往 PE 头写链接时刻，见 `shell-win/build.rs` 的
> `pin_link_timestamp()`。这条已经修掉，并且**有判据守着**，不是"知道了"。）
>
> ⚠️⚠️ **准确的说法是「同环境可复现」，不是「可复现」**（审查 2026-09-20 实测）：
> 本脚本这条路（`build_windows.sh` 的全套环境）**同树连跑两次逐字节相同**；
> 但拿**裸 `cargo build`**（环境与脚本那次不同）去链，会得到一个**同长度、不同字节**
> 的 exe —— 机理**未查清**（不是时间戳：两种产物的 `Time/Date` 都是 0）。
> ⇒ 这条判据管的是"**同一条构建路径**（本脚本）重复跑是否稳定"，它**不**声称
> "换一种构建方式也得到同一份字节"。**别把前者读成后者。**

**运行期依赖（唯一一个）**：**WebView2 Runtime**。Windows 11 自带；Windows 10 需要装
（Edge 装了就有）。本版**不做** bootstrapper 自动安装 —— 缺了它应当看到一条**说得清**
的错误（第 18 条）。

## 0b. 怎么测：自动化入口

```bash
bash windows/scripts/test.sh          # 全绿 ⇒ EXIT=0
```

大致步骤（逐条写在脚本头部）：字体子集覆盖判据 → `shell-core` 依赖守卫 →
前端文案与夹具的漂移判据 → **四套整屏验收**（无头浏览器）→ 先重建**宿主**内核 →
跑 `cargo test -p shell-core -p shell-win` → **空跑绿灯判为失败**。
最后一行打印 `test.sh: 实际运行用例数（所有 'running N tests' 行之和）：N`
—— 那一行是"真的跑了多少条"的凭据，`N == 0` 会被判成失败。

**四套整屏验收**各给一行 `ok= / fail= / abort=`：

| runner | 跑的屏 |
|---|---|
| `check_frontend_stub.sh` | 常驻 stub（注入的 `window.__TAURI__`） |
| `check_files_screen.sh` | 文件页**三档**：`sub` 35 条 + `blocked` 9 条 + **`keep` 15 条** |
| `check_transfers_screen.sh` | 传输列表屏（43 条） |
| `check_panels_screen.sh` | 工具栏下载按钮 / 换码面板 / 设置 / 关于 / 许可 / **对位差分**（108 条） |

> 🔴 **`keep` 那一档是本代最严重那个缺陷的回归网，别把它读成"又一次重复"。**
> 它跑的是：**选一个文件 → 去「传输列表」看一眼 → 切回来 → 点「下载选中」**。
> 真机上报回来的缺陷正是这条路上的一步之差 —— **切回来之后勾选面被打回默认面**，
> 于是那一下点的是**整批**（而屏幕上看起来只是"勾了没反应"）。
> `sub` 那一档从头到尾没换过屏 ⇒ 那条缺陷在它那里与"做对了"**一模一样**。
> 它对应的 Rust 判据是 `presentation/browser_row.rs` 的 `ManifestTracking`
> （「同一次加载内不重播」）—— 那一条**今天没有生产调用者**，行为由
> `web/js/screens/files.js` 承接，账与守卫见 §2 第 10 条。

> ⚠️⚠️ **它们跑的是注入的 stub，证明的是「渲染」，不是「集成」。**
> 这一点对第 8 条（传输列表的动作）**尤其要记住**：传输列表那一套（43 条）与别处的
> 那几套一样，证明的是"给定这份载荷，这一屏画得对、点得动"，
> **不证明**"这个动作真的到了内核、内核真的暂停了那一条下载"。后者只有真机这条清单能给。
>
> 🔑 **唯一的例外是那一组"对位差分"**（`check_panels_screen.sh` 里的 ⑦，19 条）：
> 它比的不是"画得对不对"，而是**同一组输入喂给 Rust 与前端、两边的结论一不一样**
> （用例表由 Rust 倒出来，见 §2 第 10 条）。它仍然是 stub 上的，所以它**不**证明
> "动作到了内核"—— 它证明的是**两边对同一件事的判断没分叉**（本代最严重那个缺陷的形状）。

> ⚠️ `test.sh` 硬依赖 **`python3`** 与**一个 Chromium 内核的浏览器**：
> 前者是依赖守卫与字体判据要的，后者是四套整屏验收要的（为什么必须是 Chromium：
> 交付形态的 webview 是 WebView2，也就是 Chromium）。**两样缺了都会当场失败
> （退出码 1，绝不跳过）**，报错里带三行平台补救。
> 在 Windows 机器上 Edge 是系统自带的，所以通常什么都不用装 —— 想先确认：
> `ls "/c/Program Files (x86)/Microsoft/Edge/Application/msedge.exe"`。
> 逐条的安装/验证步骤在 `docs/superpowers/2026-09-19-windows-dev-setup.md` §1.6。

#### [x] 17. 🔴 `CoreClient::call` **没有每请求超时**（一条仍敞着的洞）

**这一条不用专门去试，但请知道它存在、并在撞见时认出来。**

壳的每一个 `invoke` 最终都落到 `shell-core/src/client.rs` 的 `call()` 上：它写出一条
请求，然后**一直等**那条响应。**没有超时**。

* **什么情况下会挂住**：内核**答非所问**时。协议里 `id == 0` 是内核的保留值
  （连 id 都读不出来的畸形输入）——`call()` 会把它当成一条告警**记下来、然后接着等**。
  于是**只要有这么一条告警插进来，或者内核干脆不回话，对应的那个 `invoke` 就永久挂住**
  （界面上的表现是：某一块一直转圈，点别的也没用）。
* **已经被堵掉的那一半**（别把它当成还开着）：**请求行过长**这一条路已经堵死了 ——
  `call()` 在**写出去之前**就按 8 MiB 拦下并返回一句可读的原文
  （`ClientError::RequestTooLong`），所以"全选一个大批次 ⇒ 超长行 ⇒ 内核回一条
  `id == 0` ⇒ 永久挂住"那条链**不再成立**。
* **看不到时说明**：真撞见了（某处永久转圈），请把**当时在做什么**记下来 ——
  这是判断"要不要加每请求超时"唯一缺的那份现场证据。
* **谁验过**：✅ **2026-09-20 真机通过**（人类伙伴；本次验收的那一个 exe 见本节开头）。

## 2. 已知限制（**先说清楚，别把它们当缺陷报**）

1. **单实例、单窗口。** 不做多窗口（macOS 的 ⌘N 新窗口不移植），
   也不做"关窗后点任务栏图标重开那一个"那套状态机 —— Tauri 下**关窗就是退出**。
2. **不做**：自动更新、安装器（NSIS/MSI）、代码签名、主题跟随系统深浅色
   （界面**固定浅色**）。
3. **内核死亡的自动重启只有"手点一次重试"。** 上游 macOS 那套"至多一次自动重启"
   是有状态的（预算按用户动作计），**明确不在本代范围**。
   ⇒ 真机上看到"内核没了要手点一下重试"，**那是预期行为**。
4. **三个仍然点得动的入口 —— 它们是**有意**留着的，不是漏网**（按下去都有可见回应）：
   文件页失败态中央那颗「重试」、面包屑右边那颗「重新读取这一层」、
   传输列表行菜单里的「在资源管理器中显示」。前两颗只读清单、**不碰引擎**；
   第三颗**不走内核**，它的准入只有"这一行有没有路径映射"。
   而文件页底栏的「全选」「全不选」**也不在闸门名单里**、也不该在：
   它们一个内核请求都不发。
5. **字体子集有两条豁免**（逐条理由在 `make_font_subset.sh` 的豁免清单里）：
   `U+FE0F`（变体选择符 VS16，内核错误原文里的 `⚠️` 带它 —— 它在 Noto Sans SC 里
   零宽度、没有字形，缺了只是退回文本呈现，**不会**渲染成豆腐块）；
   `U+1F642`（🙂，只在一条 `#[test]` 字符串里，**永不进界面**）。
6. **"零告警"的口径**：`test.sh` 里 `core/` 的 **4 条 `dead_code` 告警**是**已知基线**
   （逐条点名在脚本头部），**任何新增告警都算回归**。
   ⚠️ 这个口径说的是 `cargo build` / `cargo test` 的告警，**不含 `clippy`** ——
   本代**没有**跑 clippy。
7. **`e2e_core.rs` 有一条已知的偶发红**（`the_core_exits_after_shutdown_and_leaves_no_orphan`
   里那句"写向死管道必须报错"）。它是**用例自己的时序竞态**，与产品行为无关：
   单独重跑 3 次全过。已如实记账、**没有按掉**。跑 `test.sh` 撞见它时先单独重跑一次。
8. **许可判据 ③ 的判别力弱**（复审实测）：`build_windows.sh` 的许可段四道网里，
   ③「产物里有登记值」的唯一可达失败形态是"sha256 常量整个从二进制里消失"，
   而那已经被 ① 与长度下限先接住。四道网**合起来**的效力边界是：
   把磁盘原件换成一段 **≥ 长度下限**的 stub **并把登记值一起改掉** ⇒ 四道一起绿。
   拦住那种改法的**只有人**在 diff 里看见"有个常量跟着换了"。
